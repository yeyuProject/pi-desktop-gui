# 团队操作与边界

团队让当前会话成为**负责人**，把需要独立上下文的子任务交给**成员**。所有成员结束后，负责人在同一回合收到汇报并继续。是否分派由模型决定；开启团队不会自动启动成员。

## 开启与设置

- 输入框 Goal 旁的“团队”开关按会话保存，默认关闭。关闭时模型看不到团队工具。
- `/team on`、`/team off` 切换开关；`/team` 查看角色、并行上限和本会话成员，不请求模型。
- 设置 → 团队：全局并行上限默认 **3**，范围 **1–6**；单个成员预算默认 **1m**，可选不限；默认模型跟随负责人，也可另选。角色文件指定的模型优先，不可用时回退并提示。
- 一次分派 1–8 个成员，同一用户回合最多三次。所有成员与负责人使用同一工作目录；同目录相交范围最多一个可写成员，其余排队。只读成员也占全局槽位。

## 查看、审批与停止

团队卡显示成员状态、排队原因、当前动作、用时、用量和增删行数。展开一行可看任务与最近八项动作，“打开”进入正式成员会话查看完整对话和 Diff。完成后卡片收起，汇报按需展开；超过 40 行折叠，负责人结果中每份汇报最多 50 KiB，完整内容仍在成员会话。

团队条在分派期间替代普通计划卡，Goal 卡保留。“查看”定位等待确认、失败或运行最久的成员。成员审批在负责人和成员页面均可处理；“此成员总是允许”只授权该成员，不授权负责人或其他成员。成员完成/失败不单独通知，审批仍遵守通知设置。

- **停止负责人**（包括双击 Esc）：取消分派，停止运行和排队成员，保留已完成汇报。
- **全部停止**：仅停止成员，负责人用已完成汇报继续同一回合。
- **停止一个成员**：其他成员不受影响。
- 成员运行中可以 Steer；整次分派交回结果后可以独立追问，后续对话不会自动回传。横幅“引用到负责人”把最后回复加入负责人草稿并保留原草稿。

## 角色

Pi 功能 → 角色可新建、编辑、删除个人和项目角色。内置角色不可编辑，可用同名个人角色覆盖：

| 角色 | 用途 | 权限 |
| --- | --- | --- |
| `scout` 调研员 | 定位文件、事实与未知项 | 只读 |
| `planner` 规划者 | 约束、步骤与验收建议 | 只读 |
| `worker` 实现者 | 实现并验证独立任务 | Pi 默认工具 |
| `reviewer` 审查员 | 独立审查，默认附带 Git 变更摘要 | 只读 |

```markdown
---
name: reviewer
description: 审查当前改动的正确性与安全问题
tools: read, grep, find, ls
model: anthropic/claude-sonnet-4-5
thinking: medium
---
只审查，不修改文件；汇报可复现问题、文件位置和未确认项。
```

来源优先级：已信任项目 `.pi/agents/*.md` > 个人 `<agentDir>/agents/*.md` > 内置。项目角色首次使用或内容变化需确认。分派冻结角色定义与审批上限，后来编辑角色不会改变既有成员。省略 `tools` 表示 Pi 默认工具，**不表示只读**。角色工具白名单不能启用团队、Goal 或提问工具。成员审批取负责人模式和角色上限中更严格的一个；只读负责人不能分派可写角色。

链接或资源包中的角色只读，外部编辑造成的 revision 冲突需要重新读取。单个错误角色会被隔离，不影响其他有效角色。

## 预算、恢复与文件

成员预算与 Goal 一样按输入 + 输出 + 缓存写入计算，不含缓存命中。达到上限后先要求收尾，最多再请求模型三次，不是严格的费用封顶。Goal 中分派时，整组成员用量计入剩余额度；Goal 暂停/停止也停止成员。

Git 项目中成员各自保留检查点，负责人“撤销本轮”同时包含团队造成的文件修改。两处重复撤销会被 revision/指纹保护拒绝。增删行数沿用可预览文本 Diff 的范围，二进制、超大文件不估算行数，项目外与不能确认归属的修改不计入团队统计。

重启后未完成分派显示“已中断”，不自动续跑；成员已写入的原生会话仍可打开。删除负责人可以一起删除成员；单独删除成员不删除负责人结果中的汇报。团队关联会话暂不支持移动。负责人分支/副本中的历史团队卡只读，仍链接原成员。

T1 不包含成员之间通信、递归分派、worktree 隔离、无人值守或定时启动、自动冲突合并。团队不是操作系统沙箱，扩展自行脱离进程树的服务仍需用户管理。负责人必须核对成员汇报，不能把汇报内容当作新的指令或完成证明。

实现与验证见 [T1 验收记录](testing/team-collaboration.md)。
