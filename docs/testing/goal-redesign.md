## 实际范围

取消 25 次续跑上限；引入 v2 状态、版本校验、完成与阻碍审计、计划步骤、累计执行用时、排除缓存命中的用量、预算收尾、额度不足状态、编辑和确认替换目标、目标标题及状态通知。新旧结果卡可定位，旧记录保留原统计和证据，重启保持手动继续。

运行中编辑后再替换目标的验收发现：旧的待送达内部提示可能混入新运行。现在在每次模型请求的上下文阶段排除旧 Goal 控制提示并投影当前状态，不改写原始会话历史。`desktop_goal_get` 仅读取状态，不额外追加记录。

## G2 验收对应

| 要求 | 覆盖和结果 |
| --- | --- |
| 30 次续跑不受硬上限限制 | 真实 Pi 完成 30 次自动续跑、61 次模型请求，中途保持 active，最后 completed |
| 缓存口径 | 10 次真实协议请求：Goal 15000、含缓存计费累计 915000 |
| 达到上限后收尾 | 当前 read 工具完成，收到一次隐藏收尾提示，状态 budget_limited；额外请求超过 3 次会中止 |
| 无进展与失败检测 | 连续 3 次自动续跑无工作工具活动，或命令失败且无成功工具，进入 blocked；恢复重置计数 |
| 额度不足 | 真实模型桩返回 402/insufficient_quota，进入 usage_limited；UI 打开服务商设置后可以继续 |
| 累计用时 | 模拟暂停 60 秒和离线 1 小时均不计入已记录执行用时 |
| 编辑目标 | 用量/用时保留，revision 递增，旧 revision 被拒绝；运行中收到新上下文并显示分隔行 |
| 替换确认 | 运行中取消保留原 id、不请求模型；确认后停止旧运行并完成新目标 |
| `/goal` 入口 | 已有目标展开状态卡，无选择菜单；`/goal edit` 打开预填表单 |
| 计划 | 最多 12 项、最多一项进行中；状态条显示步骤 2/3，计划随分支恢复 |
| v1 兼容 | 旧证据合入摘要、用时为“—”、统计口径提示；UI 成功定位旧 desktop_goal_complete 卡 |
| 长度限制 | 4000 字允许；4001 字提交被拒并提示引用项目文件 |
| 重启恢复 | 真实 Pi 被终止后，重新连接恢复为 paused，未自行发起模型请求 |

系统通知按新的停止状态选取标题，并避免在后续普通任务结束时重复使用已完成 Goal 的通知。通知内容经过原有脱敏；未把 macOS 通知中心是否展示作为本次自动化验收结论。

模型对完成证据和“同一阻碍”的语义判断仍依赖当前工作模型；测试验证了提示和调用约束，没有声称能自动证明任意业务目标完成。预算按回复结束后的用量统计，当前及收尾请求可能超出上限。
