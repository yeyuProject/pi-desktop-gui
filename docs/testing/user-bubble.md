# UI10 用户消息气泡验证

2026-11-03，Windows，Node 22.23.1，Electron 44.7.0。基于 `docs/user-bubble-prd` 的 UI10，修改位于 `codex/prd-review-fixes`。

## 实现

- 用户消息外层占满对话列。三套外观共用气泡宽度 `min(80%, 620px)`、内边距 `10px 14px` 和行高 1.6，分别保留原有背景和圆角。
- 时间和按钮移到下方，右对齐。26px 高的操作栏使用现有 28px 消息间距，不增加标题空行。鼠标悬停或键盘聚焦消息时显示；Tab 可先聚焦消息，再依次进入内部内容和操作按钮。
- 按钮顺序为复制、撤销此轮、编辑、分支、更多；撤销仍取决于检查点是否存在。普通消息没有更多菜单；只有可编辑输入与完整内容不同时才提供完整复制。
- 用户消息的「你」保留给读屏。Goal 起点标记保留可见，移到对应气泡内。助手消息的标题、操作和回复布局保持原样。

## 宽度验收

用户确认保留 80% 上限，窄窗口正常换行，不调整面板宽度。验收第 1 条已改为：折行气泡宽度应达到 `min(实际对话列宽 × 80%, 620px) − 一个字宽`，单行不设宽度下限。第 2 条的最大宽度限制保持原样。

| 窗口宽度 | 对话列 | 30 字气泡 | 30 字行数 | 原问题中的短句 |
| -------- | ------ | --------- | --------- | -------------- |
| 1200px   | 466px  | 372.80px  | 2         | 1 行           |
| 1440px   | 706px  | 448px     | 1         | 1 行           |

以上展开面板的结果在经典、Codex、Claude 的明暗六种组合中一致；Claude 原问题短句的宽度为 263.63px，其余为 264.69px。示例 A 在 1200px 收起变更面板后，对话列为 746px（经典）或 754px（Codex、Claude），同一条 30 字消息均为一行。示例 B 展开面板后为两行，气泡宽度达到实际列宽的 80%；两例在六种外观中全部通过。测试明确设置并核对渲染器 CSS 视口宽度，避免 Windows 离屏原生窗口边框带来的尺寸偏差。
