# UI12 发送延迟验收

日期：2026-11-04。基线：v0.14.66 之后的 `60e3479`。环境：Windows x64，真实 Pi CLI 和本机模型接口。

## 改动

- **主进程。** 发送被 Pi 受理并清空草稿后，`sendInOperation` 在 `activity()` 之后立即保存，不再等忙碌期的 2 秒合并。`SessionAgents` 的状态去重除原有字段外，还按引用比较每个会话的 `draft`、`attachments`、`images`、`draftSnippets`、`draftQuotes`。写草稿的地方都整体替换这些字段，所以发送清空、恢复队列、外部编辑导入、侧边对话续问等都会广播，不会再被去重吞掉。
- **界面。** 普通消息（不是 `/` 命令、`!` 终端命令、Goal 输入或模型提问的回答）按回车后：
  - 先发出草稿保存，再立即清空输入框，只改界面，不写盘；磁盘草稿仍由主进程在 Pi 受理后清空。
  - 空闲时，消息列表末尾显示「发送中…」占位；运行中，队列条显示「发送中」一项。
  - 真实消息出现的同一次渲染中移除占位。Pi 受理后 15 秒仍未出现用户消息（例如扩展处理了它）也移除。
  - Pi 受理后，输入框保持为空，直到清空草稿的状态到达；3 秒内没有到达时以磁盘草稿为准。
  - 发送失败时，没有新输入就把正文、附件、图片、粘贴片段和引用原样放回；已有新输入时保留新输入，并提示「上一条消息没发出去」，可点「恢复到输入框」把旧内容接在前面。
  - 发送期间继续输入不会再取消这次发送。

## 验证

- `scripts/test-send-latency-ui.mjs`（`npm run test:send-latency-ui`，已加入 CI 的 Linux 任务）：在 `send` 前人为延迟 1 秒，逐帧记录输入框和消息列表。
  - 空闲发送：按回车后 18 ms 输入框为空、占位出现；之后每一帧输入框都不含原文，占位和真实消息没有同时出现；发送期间磁盘草稿仍是原文。真实消息约 3.3 秒后出现（含 1 秒人为延迟和首次连接 Pi）。数字见 `test-results/send-latency.json`。
  - 发送失败：内容回到输入框，显示错误条。
  - 发送期间输入新内容后失败：新内容保留，「恢复到输入框」后两段都在。
  - 运行中发送：队列条先显示「发送中」，再变为「补充」；输入框始终不含原文。
- `tests/session-agents.test.ts`：状态不变时，只改草稿也会广播。
- 回归：`npm test` 847 项（837 通过、10 项平台跳过、0 失败）；`test:chat-ui`、`test:ui`、`test:optimizations-ui`、`test:feedback-motion-ui`、`test:motion-ui`、`test:goal-ui` 通过。`tests/workbench-selection.test.ts` 中「保存屏障期间修改草稿会取消发送」改为只针对 `/` 命令等非即时清空的发送，另加普通消息先清空、之后的修改不取消发送的用例。macOS、Linux 未在本机运行。
