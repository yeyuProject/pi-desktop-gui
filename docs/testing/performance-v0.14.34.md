# v0.14.34 性能验证

2026-10-23，Windows 本机、Node 22.22.0、Electron 44.7.0，生产构建。基线为 v0.14.33（f44eda2）。同机相同合成数据与测试脚本前后对比；所有数据均隔离在测试目录，不使用真实模型或凭据。数字不是跨设备承诺。

| 场景 | v0.14.33 | v0.14.34 |
| --- | ---: | ---: |
| 500 条消息，当前 5 万字符 Markdown，流式更新中位数 / P95 | 151.6 / 204.6 ms | 15.1 / 16.1 ms |
| 刚输入后切换会话，中位数（10 次） | 331.8 ms | 15.9 ms |
| 5000 条消息，渲染器 GC 后 JS 堆 | 18.40 MiB | 8.74 MiB |
| 5000 条消息的轮次导航按钮 | 2500 | 60 |
| 8 MiB 用户图片未变化时，主进程发布流式补丁中位数 | 20.75 ms | 0.007 ms |
| 12 个各含 1 MiB 图片的草稿，状态复制中位数 | 19.5 ms | 0.034 ms |
| 8.35 MiB 历史重复读取中位数 | 26.76 ms | 7.72 ms |
| 33.42 MiB 历史读取期间最大事件循环延迟 | 156.5 ms | 41.2 ms |

UI 更新耗时包括测试 IPC、React 更新与下一动画帧；35 次更新预热 5 次后统计 30 次。优化后该长 Markdown 场景观察期未记录超过 50 ms 的任务。JS 堆是在强制 GC 后测量，不代表整个 Electron 应用的常驻内存或峰值。未输入时的切换中位数约 16 ms，但首次环境检测重叠时仍出现 738 ms 的单次离群值。

历史计时不包含 UI/IPC；小文件采用暖缓存，大于 16 MiB 的文件不缓存。大文件仍整体读取并返回，尚未实现历史分页或工作线程；33 MiB 样本中 GC 前主进程堆并未下降，不能将分段让出事件循环描述为全面降低峰值内存。缓存预算是估算数据容量，另有对象开销。

## 持续验证

- `npm run build`、`npm test`、`npm run test:integration`：类型与构建、缓存失效、调用方隔离、草稿哈希、Markdown 语义、真实 Pi RPC。
- `npm run test:ui`：图片恢复与并发输入、混合附件、重新启动、退出落盘、滚动与历史。
- `npm run test:performance-ui`：固定合成样本，保存 `test-results/performance-ui.json`；硬性检查最多 60 个导航按钮、键盘跳转、消息窗口与最终 Markdown，耗时超过 100 ms 的 P95 给出提示，避免把共享 CI 的性能抖动当成功能失败。

初次环境检测从 bootstrap 移至后台；可以更早编辑工作台，但发送仍需等待 Pi 环境就绪。首次完整 Markdown 展示与回复结束的最终排版仍可能产生长任务。
