# Pi Desktop v0.14.39

- Verify update manifests with a bundled Ed25519 publisher key before downloading installers. Add update-only proxy and HTTPS mirror settings, and read release assets without consuming GitHub API quotas. Downloads are manual by default; quitting never installs an update. Installation requires an explicit restart.
- On macOS, require the new version to finish loading its index and workbench. If startup fails, stop the newly launched process and atomically restore the previous app. Preserve existing data and pending drafts through the update flow.
- Open histories larger than 64 MiB by indexing records and loading the current branch. Large previews are bounded with a visible notice; the original history remains intact. Retry temporary save failures automatically and offer a manual retry, while retaining read-only protection for damaged data.
- Remove session checkpoints, temporary drafts, bridge files and backed-up drafts when deleting a conversation. Add a confirmed desktop-data cleanup action with an explicit scope; external projects, external Pi histories and provider credentials are excluded.
- Keep pending replies visible with a global entry and app badges, including when the sidebar is collapsed. Add keyboard approval/rejection, per-category notifications, file/hunk review navigation, and chunked diff layout.
- Improve pending-label contrast, preserve window zoom, scale fixed font sizes with preferences, add searchable workbench actions, and simplify connection errors. Retry failed shell discovery and find Pi/Node in common Homebrew, nvm, fnm, Volta and pnpm locations.

## Update verification

This is the first release with independent manifest signatures. Older clients retain their existing update verification until upgraded. New clients require the matching `.sig` alongside each platform's update manifest. Operating-system code signing is unchanged: macOS is ad-hoc signed and Windows remains unsigned, so first-launch Gatekeeper/SmartScreen prompts may still occur.

这是首个包含独立更新清单验签的版本。旧客户端升级后才获得此验证；新客户端要求每份平台清单都有对应的 `.sig`。系统代码签名状态不变，macOS 仍为 ad-hoc 签名，Windows 暂未签名，首次运行仍可能出现系统提示。
