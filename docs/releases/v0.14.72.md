# Pi Desktop v0.14.72

## Team collaboration

- Enable Team per conversation to delegate 1–8 independent tasks to managed member sessions. Members have their own context and native history, and return reports to the lead within the same user turn. Team is off by default.
- Keep execution under the existing process, approval and checkpoint managers: a shared concurrency limit (default 3), one writable member per overlapping directory, individual/all-member stop, bounded member budgets and Goal usage accounting.
- Follow work through team cards, a compact team strip and grouped member sessions. Handle approvals from the lead without sharing grants, open member history, search reports or quote a report back while preserving the lead's draft.
- Manage built-in, personal and trusted-project Markdown/YAML roles. Project role changes require confirmation; running members retain their approved role and permission ceiling.
- Preserve completed reports on cancellation and deleted-member history. Interrupted teams reopen without automatically resuming; Git-project member changes participate in the lead's per-turn undo.

T1 only: no nested delegation, member-to-member messaging, worktree orchestration, unattended scheduling or automatic conflict merging. See [team controls and boundaries](https://github.com/yeyuProject/pi-desktop-gui/blob/v0.14.72/docs/team.md).

Local validation: build, lint and formatting passed; 864 unit tests passed with 2 platform-specific skips. Real Pi integration, Goal and feature regressions, team UI, plan/approval/update UI and an isolated signed Mac directory build passed. The release workflow runs three-platform integration and team UI, Windows/Linux installer upgrade regression and packaging. Tests use isolated data and a deterministic local provider, not cloud-model quality or billing checks. See the [acceptance record](https://github.com/yeyuProject/pi-desktop-gui/blob/v0.14.72/docs/testing/team-collaboration.md).

## 中文

### 团队协作

- 按会话开启团队，负责人可分派 1–8 个独立任务。成员有独立上下文和正式原生历史，所有汇报在负责人的同一用户回合返回。团队默认关闭。
- 复用现有进程、审批和检查点管理：全局并行上限默认 3，相交目录最多一个可写成员，支持停止单个或全部成员、成员用量上限及 Goal 用量合计。
- 团队卡、团队条和侧栏分组展示进度；可在负责人页面处理成员审批，但授权不共享。支持打开成员历史、查找汇报、引用到负责人并保留原草稿。
- 在 Pi 功能中管理内置、个人和已信任项目的 Markdown/YAML 角色。项目角色变更需要确认，运行中的成员保留已确认的角色定义和权限上限。
- 取消时保留已完成汇报，删除成员后仍可阅读历史结果。中断团队重开后不自动续跑；Git 项目成员修改纳入负责人按轮次撤销。

本次仅包含 T1，不包含成员再分派、成员间通信、worktree 编排、无人值守调度或自动合并冲突。详见[团队操作与边界](https://github.com/yeyuProject/pi-desktop-gui/blob/v0.14.72/docs/team.md)。

本地验证：构建、lint、格式检查通过；864 项单测通过，2 项按平台跳过。真实 Pi 集成、Goal、功能回归、团队 UI、计划/审批/更新 UI，以及隔离的签名 Mac 目录包验证通过。发布工作流执行三平台集成与团队 UI、Windows/Linux 安装包升级回归和打包。测试使用独立数据及本地确定性 provider，不代表线上模型质量或云账单验证。详见[验收记录](https://github.com/yeyuProject/pi-desktop-gui/blob/v0.14.72/docs/testing/team-collaboration.md)。
