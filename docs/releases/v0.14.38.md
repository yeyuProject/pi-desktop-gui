# Pi Desktop v0.14.38

- Harden confirmation-mode command approvals: remembered shell approvals now match the complete command text. Changing arguments requires a new confirmation, and legacy prefix grants are no longer honored.
- Require individual confirmation for writes to `.git`, `.pi`, `.gitattributes`, and `.gitmodules`, including paths reached through links. A project-wide write grant covers ordinary project files only.
- Check project trust before launching repository Git operations. Untrusted projects can still browse and search files without executing repository-configured Git commands; the changes panel explains why Git status is unavailable.
- Verify read and search targets before automatically allowing them. Confirm mode asks separately for each outside or unverifiable path; read-only mode blocks those requests. Path aliases and links are resolved before checking the project boundary.
- Keep approval revocation and session isolation intact, with regression coverage using a real Git filter and actual Pi desktop approval flows.

## 中文

- 收紧确认模式下的命令授权：记住的授权只匹配完整命令文本，更改参数需要重新确认，旧的命令前缀授权不再生效。
- 写入 `.git`、`.pi`、`.gitattributes` 和 `.gitmodules` 必须单独确认，包括通过链接访问的路径。「允许修改项目内文件」仅覆盖普通项目文件。
- 启动仓库 Git 操作前检查项目是否受信任。未信任项目仍可浏览和搜索文件，但不会执行仓库配置中的 Git 命令；变更面板会提示尚未读取 Git 状态的原因。
- 自动放行读取与搜索前验证目标路径。确认模式对项目外或无法验证的路径每次单独询问；只读模式直接拒绝。路径别名与链接在判断项目边界前解析。
- 保留授权撤销和会话隔离，并使用真实 Git filter、Pi 工具及桌面审批流程进行回归验证。
