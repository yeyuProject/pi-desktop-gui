# Pi Desktop v0.14.75

## Conversation fixes

- Open local file links in replies. Links to generated reports, tables, images, audio and other documents (absolute paths, `file://` or `~/`) now open with the system default app, and plain folders open in the file manager. Previously these links did nothing.
- Never launch programs from a reply link. Scripts, apps, packages and unknown file types are only revealed in the file manager, or opened in the configured code editor. The decision uses the real target of a symlink. A missing or unsupported link now shows a message instead of failing silently, and hovering a link shows its full target.
- Keep a tool card above the final reply when a message you sent during a running command is delivered together with that command's result. Previously the card could appear below the final reply until a later tool result arrived or the conversation was reopened.

Local validation: build, type checking, lint and formatting passed. 873 unit tests ran: 870 passed and 2 were platform-specific skips. One file-watcher timing test timed out under full-suite load; it is unrelated to these changes and passed three consecutive isolated reruns. New regression tests cover the tool-result-with-steering-message order and reply link handling. In an isolated app build, clicking a report link opened it, a script link was only revealed, and a missing file showed an error. Conversation, transcript and scroll UI tests passed.

## 中文

### 对话修复

- 回复中的本地文件链接可以打开：指向生成的报告、表格、图片、音频等文档的链接（绝对路径、`file://` 或 `~/`）会用系统默认程序打开，普通文件夹在文件管理器中打开。此前点击没有任何反应。
- 回复链接不会启动程序：脚本、应用、安装包和未知类型的文件只在文件管理器中定位，或用已设置的代码编辑器打开；对符号链接按实际目标判断。文件不存在或链接不受支持时给出提示，不再无声失败；悬停链接可查看完整路径。
- 命令运行期间发送的补充消息与该命令的结果一起送达时，工具卡仍显示在最终回复之前。此前它可能出现在最终回复下方，直到出现新的工具结果或重新打开会话。

本地验证：构建、类型检查、lint、格式检查通过。873 项单测中 870 项通过，2 项按平台跳过；1 项文件监视计时测试在完整测试负载下超时，与本次改动无关，单独连续重跑 3 次均通过。新增回归测试覆盖“工具结果与补充消息同时送达”的顺序和回复链接处理。在隔离构建中点击报告链接可打开，脚本链接仅定位，缺失文件给出提示；对话、历史记录和滚动 UI 测试通过。
