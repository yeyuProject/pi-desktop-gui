# Pi Desktop v0.14.78

## Layout fixes

- Keep the conversation at least 520 px wide. The side conversation now opens as a drawer whenever it would leave less room than that, taking an open Changes panel into account. Previously it only became a drawer in windows narrower than 900 px, so with both panels open the conversation could shrink to about 300 px.
- When the Changes panel is open beside the conversation, the side conversation drawer covers it exactly instead of leaving a strip of it visible.
- Wrap whole controls in a narrow composer toolbar in every style. Previously only the Claude style did this; in other styles labels such as the approval mode broke into a vertical column and the model name could spill outside the composer.

Local validation: type checking, lint and formatting passed. 873 unit tests ran: 862 passed and 11 were platform-specific skips. Classic, Codex and Claude style checks passed with unchanged computed-style baselines. In window widths of 860, 1200 and 1456 px with both panels open, the conversation stayed at least 560 px wide and the composer toolbar did not overflow. The chat UI test passed in full before a final change that only limits re-rendering during window resizing. After that change it stopped at different timing-sensitive steps between runs, as the unchanged code also did on this machine.

## 中文

### 布局修复

- 对话区至少保留 520 px 宽度。侧边对话在会让对话区窄于此宽度时改为抽屉打开，并计入已打开的变更面板。此前只有窗口窄于 900 px 才使用抽屉，两个面板同时打开时对话区可能被挤到约 300 px。
- 变更面板在对话区旁打开时，侧边对话抽屉正好覆盖它，不再露出一条边。
- 所有风格下，输入框工具栏变窄时按整个控件换行。此前只有 Claude 风格这样处理；其他风格中审批模式等文字会竖排，模型名可能超出输入框。

本地验证：类型检查、lint、格式检查通过。873 项单测中 862 项通过，11 项按平台跳过。经典、Codex、Claude 风格检查通过，计算样式基线不变。窗口宽 860、1200、1456 px 且两个面板同时打开时，对话区宽度不少于 560 px，工具栏无溢出。对话 UI 测试在最后一处改动前完整通过；该改动只减少窗口缩放时的重新渲染，之后多次运行在不同的计时敏感步骤失败，未改动的代码在本机同样如此。
