# Pi Desktop v0.14.81

## Jump to the conclusion

- When a task finishes and the start of the final reply is above the visible area, a "跳到结论" button appears above the composer. Clicking it brings the first line of the reply to the top of the conversation, below its thinking block, and briefly highlights it. "回到最新" then returns to the end.
- The button does not appear while a task is running, while an approval is pending, when the reply's start is already visible, when the last turn has no text reply, or when the whole reply is above the visible area.
- Sending a new message after any jump now follows the new output. Previously a jump could pull the view back to its old position whenever new messages arrived.

## Composer toolbar

- The toolbar always stays on one row. In a narrow composer, Goal, 团队, the approval mode and 停止任务 show only their icons, then the send hint is hidden, and the model name is shortened with an ellipsis. Previously the right-hand controls dropped onto a second row.
- The approval mode menu lists its three modes vertically again. Since v0.14.78 they were laid out side by side and overflowed the menu.

Local validation: type checking, lint and formatting passed. 875 unit tests ran: 864 passed and 11 were platform-specific skips. The conversation, approval and style UI tests passed, with unchanged computed-style baselines for the Classic, Codex and Claude styles. In a built app, the toolbar stayed on one row without overflow in all three styles, idle and running, at window widths from 640 to 1440 px, and the approval menu items were stacked. With the new button, the 95th percentile scroll handling time per frame rose from 0.4 ms to 0.5 ms.

## 中文

### 跳到结论

- 任务结束后，如果最终回复的开头在可见区域上方，输入框上方会出现「跳到结论」按钮。点击后回复的第一行停在对话区顶部（跳过前面的思考块），并短暂高亮；之后可以用「回到最新」回到末尾。
- 任务运行中、有待审批项、回复开头已经可见、最后一轮没有文字回复，或整条回复都在可见区域上方时，不显示按钮。
- 任何跳转之后发送新消息，视图都会跟随新输出。此前新消息到达时，视图可能被拉回上次跳转的位置。

### 输入框工具栏

- 工具栏始终保持一行。输入框变窄时，Goal、团队、审批模式和停止任务只显示图标，再窄时隐藏发送提示，模型名用省略号缩短。此前右侧控件会掉到第二行。
- 审批模式菜单恢复纵向排列三种模式。自 v0.14.78 起它们横向排开并超出菜单。

本地验证：类型检查、lint、格式检查通过。875 项单测中 864 项通过，11 项按平台跳过。对话、审批和风格 UI 测试通过，经典、Codex、Claude 风格的计算样式基线不变。在构建的应用中，三种风格在空闲和运行中、窗口宽 640 到 1440 px 时，工具栏均保持一行且无溢出，审批菜单纵向排列。加入新按钮后，每帧滚动处理耗时的 P95 从 0.4 ms 升至 0.5 ms。
