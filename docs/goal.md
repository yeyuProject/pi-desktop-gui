# Goal：持续执行一个目标

Goal 随 Pi Desktop 的桌面扩展加载，无需安装社区插件。执行工作和判断完成都使用当前会话的模型，不增加独立验收模型。

## 使用

点击输入框工具栏的 **Goal** 按钮，在一个对话框中填写目标即可开始。“高级：用量上限（可选）”默认折叠，上限默认“不限”，也可选择 `500k`、`2m`、`5m` 或自定义正整数。取消不会开始模型请求，输入框里原有的草稿会保留。

输入框上方的一行状态条显示续跑次数，可直接暂停或继续。达到用量上限暂停后，点击“调整上限并继续”，增大上限或选择“不限”，确认后继续。点击箭头可查看目标全文、摘要、Markdown 证据和用量，详情最高占窗口的 40%，按 `Esc` 收起。“跳到结果”会定位到对话中的完成工具卡。

完成后 8 秒内没有展开或悬停，状态条会收起为 Goal 按钮上的绿色圆点，点击按钮可重新查看。`×` 清除目标；未完成的目标会先确认“清除后不再自动继续，已完成的修改保留”，已完成的目标直接清除。清除后可以新建目标。

也可以在输入框发送命令：

```text
/goal 修复登录校验，运行相关测试，并说明每项要求的验证结果
/goal --tokens 100k 完成接口迁移，确保构建及现有回归测试通过
```

目标和执行状态显示在输入框上方。连接 Pi 后，命令选择器也会显示 `/goal`。

| 命令                        | 行为                                                    |
| --------------------------- | ------------------------------------------------------- |
| `/goal`                     | 打开当前目标的操作菜单                                  |
| `/goal status`              | 查看目标状态                                            |
| `/goal [--tokens N] <目标>` | 创建并开始一个目标；预算参数必须放在目标前面            |
| `/goal pause`               | 暂停目标并停止当前运行，保留进度                        |
| `/goal resume`              | 恢复目标，保留累计 Token 用量，重新计算本次自动续跑次数 |
| `/goal clear`               | 清除目标并停止该目标的自动执行                          |

`N` 可以是正整数或带 `k`、`m` 的数量。一个会话分支同时保存一个目标；替换未完成目标前，先明确清除它。普通补充消息继续使用当前目标。

用量是供应商上报的每次请求累计输入、输出与缓存用量，包含重复发送的上下文，与底部累计数字采用相同口径，不是单次上下文占用。未设上限时，状态条不显示 Token 数字；详情统一用 `k` / `m` 显示，悬停可查看精确值和按当前会话平均单价估算的费用。设置上限时会按已有请求的平均用量估算可执行次数；没有历史数据时会说明统计口径。

## 完成与停止

模型说“完成了”不会直接结束 Goal。它必须调用 `desktop_goal_complete`，提交当前目标 ID、完成说明和验证证据。遇到必须由用户或外部条件解决的阻碍时，可以通过 `desktop_goal_blocked` 提交原因和证据。

证据字段和目标 ID 会被程序校验；证据本身仍由工作模型检查。该功能不会自动把所有业务要求转换成测试，也不保证模型声称的结果一定正确。把测试命令、预期结果和不能修改的范围写进目标，便于复核。

每次开始或显式恢复后，最多自动续跑 25 次。连续 3 个结束轮次没有调用工具时会暂停；这只是防止反复输出文字，并不等同于程序能够判断所有工作的实际进度。达到用户设置的 Token 预算后也会停止自动工作。供应商用量在回复结束后才能确定，因此预算可能被最后一次请求超出，不能当作严格的费用上限。

现有工具审批仍然生效。两个内置 Goal 状态工具只记录会话结果，不执行工作区操作，因此在只读模式也可以记录完成或阻塞。

## 保存与恢复

目标状态通过 Pi 原生会话记录保存，不创建项目级 Goal 数据库。切换到新的会话不会继承另一个会话的目标。恢复历史分支时，以该分支保存的目标为准。

停止任务、重新加载扩展或重连后，原来正在执行的目标会暂停；已完成或遇到阻碍的目标保留原状态。重启或切换会话后，已完成的目标以圆点显示。点击状态条的 **继续**，或使用 `/goal resume`，才会重新开始模型请求。打开聊天或读取历史不会自动运行目标。

## 实现边界

- `electron/pi-goal.ts` 注册命令、模型工具和原生生命周期监听。
- `electron/goal-state.ts` 定义状态及输入校验。
- 自动续跑使用 Pi 的 `agent_before_settle` 边界，等待原生工具循环、重试、上下文压缩和队列处理；直到整个任务结束才向桌面发布 `agent_settled`。
- 自动续跑的内部提示保留在原生会话上下文中，桌面对话区遵循 `display: false`，不显示这些内部提示。
- 开始和恢复通过用户消息建立检查点；其后的自动续跑属于同一次任务，沿用现有工具审批和文件检查点。

该实现基于项目锁定的 Pi 1.4.0 公共扩展 API。不要同时启用其他注册 `/goal` 的扩展，以免命令归属发生冲突。
